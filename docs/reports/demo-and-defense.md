# 软件演示与申优讲稿

## 演示路线（约8分钟）

1. **商户与权限（1分钟）**：admin审核资料；owner查看M001，otherowner查看M002/M003。说明平台角色与商户角色分层。
2. **收款与恢复（1.5分钟）**：cashier开单，提交收款；DEMO模拟通知丢失，主动或定时查询恢复；再重复通知，展示接收次数与唯一流水分别计数。
3. **部分退款（1分钟）**：customer提交部分退款，finance审批。查看可退余额、预留和状态，申请人与审批人不同。
4. **历史对账（1.5分钟）**：导入教学账单，查看错误/重复行，运行，打开金额差异双栏；重跑并比较两次结果。旧批次不改。
5. **工单协作（1.5分钟）**：finance分派cashier，检索相似案例，保存分析和证据，提交；reviewer独立复核。用新MATCHED结果结案时选择同事件证据。
6. **分析与审计（1分钟）**：商户→门店→流水、月→日→流水，展示100/30跨日例；生成PDF/Word、Excel/XML；审计员追踪相关请求与变更。
7. **真实渠道（0.5分钟）**：展示历史沙箱 0.01 元支付、查询和退款记录，说明真实签名通知与实际业务账单仍待验收。现场只有在恢复环境并重新取得结果后才展示新的成功画面。

## 答辩要点

- 订单金额为何不直接存？冻结明细汇总是唯一应收来源，资金流水另记已确认实际事件。
- 退款为何不能包在一个大事务？数据库回滚不能撤销已经在外部成功的退款，需稳定请求号与持久状态恢复。
- 关闭工单为何没有改变历史差错？旧分类描述当时观察，结案描述处理结论，新批次才表达后来结果。
- 为什么用原生全文？工单长文本需要语言相关度，SQL Server组件可直接复用已有关系和授权范围。
- 如何证明3NF？给出候选键与函数依赖，说明不保存商户名副本、明细小计和可漂移总额；历史快照具有独立事实含义。
